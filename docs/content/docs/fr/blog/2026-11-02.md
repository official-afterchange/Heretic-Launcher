Aujourd'hui, pas de nouvelle fonctionnalité dans le launcher : la journée a été consacrée à **documenter les API externes** dont il dépend. Avant d'écrire le code de téléchargement, nous voulions avoir une référence claire, écrite une bonne fois pour toutes, de ce qu'il faut appeler, dans quel ordre et avec quels paramètres.

## Pourquoi documenter les API maintenant ?

Le launcher ne contient ni le jeu, ni Java : il doit tout récupérer à la volée. Il repose donc sur deux services externes :

* **Mojang** pour le jeu lui-même (client, bibliothèques, assets) ;
* **Adoptium (Eclipse Temurin)** pour le runtime Java.

Si ces routes ne sont pas documentées, il faut les redécouvrir à chaque fois qu'on touche au code de téléchargement. Les écrire maintenant permet de coder ensuite sans repartir de zéro, et de partager la compréhension avec le reste du groupe.

## Ce qui a été fait

### Page Mojang : routes et domaines

La page [Routes et Domaines Mojang (Assets)](/Heretic-Launcher/en/api/mojang) décrit toute la chaîne de téléchargement d'une version de Minecraft, ici la **26.2**.

Le fonctionnement se résume à une cascade où chaque étape fournit les URL de la suivante :

```text
Manifeste des versions → JSON de la version → client.jar / libraries / index des assets
```

La page couvre :

* la liste des **domaines à autoriser** (utile pour un pare-feu, un proxy ou la CSP de l'application) ;
* le **manifeste des versions** et le **JSON de version**, qui est le fichier central ;
* le téléchargement du **`client.jar`** ;
* les **bibliothèques**, avec les `rules` à évaluer selon l'OS et l'architecture ;
* les **assets**, avec la formule d'URL basée sur le hash et l'organisation sur le disque ;
* les **bonnes pratiques** : vérification des `sha1`, téléchargements parallèles, retries.

Le point qui nous a le plus appris : **ces routes sont publiques**. Aucune authentification n'est nécessaire pour télécharger le jeu, ce qui est cohérent avec le fait que notre launcher gère l'authentification de son côté.

### Page Adoptium : récupérer le bon Java

La page [Routes et Paramètres de l'API Adoptium (Java)](/Heretic-Launcher/en/api/adoptium) documente l'endpoint qui permet de récupérer dynamiquement le lien de téléchargement d'un **JRE** à jour.

On y trouve :

* la structure de l'URL de base (`feature_releases/{version}/ga`) ;
* le rôle de **chaque paramètre** (`architecture`, `image_type`, `os`, `page_size`, `sort_order`, `vendor`…) ;
* des **URL prêtes à l'emploi** pour Windows, Linux et macOS.

Quelques choix à retenir :

* on demande un **JRE** plutôt qu'un JDK : plus léger, et suffisant pour lancer le jeu ;
* on garde `project=jdk` même pour un JRE, c'est le nom du projet côté Adoptium ;
* avec `page_size=1` et `sort_order=DESC`, on obtient directement **la dernière version disponible**, sans avoir à trier côté launcher ;
* sur macOS, il faut adapter `architecture` : `aarch64` pour les puces Apple Silicon, `x64` pour les anciens Mac Intel.

## Ce que l'on retient

Les deux services se complètent : le JSON de version Mojang indique **quelle version de Java** est requise (`javaVersion.majorVersion`, soit Java 25 pour Minecraft 26.2), et l'API Adoptium permet ensuite de **télécharger ce Java**. Le launcher pourra donc enchaîner les deux sans configuration manuelle.

Mojang propose aussi son propre manifeste de runtimes Java. Nous avons gardé cette option dans la documentation, mais Adoptium reste notre choix principal pour l'instant.

## Prochaines étapes

* Écrire le code Rust qui interroge le manifeste et résout la version demandée.
* Implémenter le téléchargement des bibliothèques et des assets, en parallèle et avec vérification des `sha1`.
* Brancher la détection de l'OS et de l'architecture pour choisir les bons paramètres Adoptium.
