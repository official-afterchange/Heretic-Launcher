Today, no new feature in the launcher: the day was spent **documenting the external APIs** it depends on. Before writing the download code, we wanted a clear reference, written once and for all, of what to call, in what order, and with which parameters.

## Why Document the APIs Now?

The launcher contains neither the game nor Java: it has to fetch everything on the fly. It therefore relies on two external services:

* **Mojang** for the game itself (client, libraries, assets);
* **Adoptium (Eclipse Temurin)** for the Java runtime.

If these routes aren't documented, we have to rediscover them every time we touch the download code. Writing them down now lets us code afterward without starting from scratch, and share the understanding with the rest of the group.

## What Was Done

### Mojang Page: Routes and Domains

The [Mojang Routes and Domains (Assets)](/Heretic-Launcher/en/api/mojang) page describes the entire download chain for a Minecraft version, here **26.2**.

How it works boils down to a cascade where each step provides the URLs for the next one:

```text
Version manifest → Version JSON → client.jar / libraries / asset index
```

The page covers:

* the list of **domains to allow** (useful for a firewall, a proxy, or the application's CSP);
* the **version manifest** and the **version JSON**, which is the central file;
* downloading the **`client.jar`**;
* the **libraries**, with the `rules` to evaluate depending on the OS and architecture;
* the **assets**, with the hash-based URL formula and the on-disk layout;
* **best practices**: `sha1` verification, parallel downloads, retries.

The point that taught us the most: **these routes are public**. No authentication is needed to download the game, which is consistent with the fact that our launcher handles authentication on its own.

### Adoptium Page: Getting the Right Java

The [Adoptium API Routes and Parameters (Java)](/Heretic-Launcher/en/api/adoptium) page documents the endpoint used to dynamically retrieve the download link for an up-to-date **JRE**.

It includes:

* the structure of the base URL (`feature_releases/{version}/ga`);
* the role of **each parameter** (`architecture`, `image_type`, `os`, `page_size`, `sort_order`, `vendor`…);
* **ready-to-use URLs** for Windows, Linux, and macOS.

A few choices worth remembering:

* we request a **JRE** rather than a JDK: it's lighter and enough to run the game;
* we keep `project=jdk` even for a JRE, since that's the project name on the Adoptium side;
* with `page_size=1` and `sort_order=DESC`, we directly get **the latest available version**, with no need to sort on the launcher side;
* on macOS, `architecture` must be adjusted: `aarch64` for Apple Silicon chips, `x64` for older Intel Macs.

## Key Takeaways

The two services complement each other: the Mojang version JSON tells us **which Java version** is required (`javaVersion.majorVersion`, i.e., Java 25 for Minecraft 26.2), and the Adoptium API then lets us **download that Java**. The launcher will therefore be able to chain the two without any manual configuration.

Mojang also provides its own Java runtime manifest. We kept this option in the documentation, but Adoptium remains our main choice for now.
