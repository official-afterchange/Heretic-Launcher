Today, development on **Heretic Launcher** progressed significantly on two main fronts: methodological organization with the integration of a **DevOps**-focused roadmap, and the implementation of the dependency and library download engine in Rust.

---

## Planning & DevOps Approach

To maintain a clear overview of project progress and ensure consistent engineering quality, I wrote and structured the launcher's **Planning & Roadmap** page.

This planning is broken down into **Sprints** and directly applies **DevOps** principles:
- **Continuous Integration (CI)**: Automated validation on every *push* / *merge request* (linting with `clippy`, formatting via `cargo fmt` / `prettier`, build verification).
- **Continuous Delivery (CD)**: Automated multi-platform matrix compilation (Windows & Linux) to generate packages and *releases* without manual intervention.
- **Traceability & Quality**: Strict environment isolation and milestone tracking (Proof of Concept, Offline Alpha, Modding Beta, v1.0 Release).

## Library Downloading (Mojang & Fabric)

The bulk of today's technical work focused on installing game dependencies in Rust.

### 1. Mojang Libraries: ✅ Validated
The resolution and download system for official Mojang libraries is now fully functional. The launcher can:
- Parse the version JSON;
- Filter libraries based on the current OS and architecture (evaluating `rules`);
- Download required files and verify integrity via SHA-1 checksums.

### 2. Fabric Libraries: ✅ Validated
Support for **Fabric** modding is progressing very well: retrieving and injecting the bootstrapper along with Fabric-specific libraries is now operational.

## Reflection: Server/Client Mod Synchronization

One of the upcoming challenges involves managing mods required by a custom server. We need to ensure the client has the exact same mods (and versions) required by the server before launching the game.

### Envisioned Approach (Dedicated Web Server & API)
For now, the planned idea is to set up a dedicated **Nginx web server** paired with a small API:
1. The mods required by the server are hosted and referenced there.
2. At each launch, the launcher queries this API to fetch the list and fingerprints (hashes) of the server's official mods.
3. The client compares this info with its local mod folder, then downloads, updates, or deletes the necessary files to guarantee perfect synchronization.
